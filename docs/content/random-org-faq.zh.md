## Q0：测试有一次没有通过！这是否说明这个随机源不随机？
我们的测试方法是基于给定的生成器中获取许多随机数序列,并对它们进行一系列统计测试。随着序列通过更多的测试,对数字随机性的信心会增加,对生成器的信心也会增加。

然而，随机数本质上是统计上独立的。即使在真实世界里，也可能出现“骰N次点时N次完全一致”的情况。在这种情况下，该某些序列会显得不够随机,此时某些序列至少会失败一些测试。

但如果许多序列未能通过测试,应该保持警惕。比如，如果您看到出现太多相同值的序列或者相同的模式，您应该保持警惕。

事实上,我们有理由怀疑，如果一个序列一直以完美的方式通过了所有测试,这可能意味着生成器不会生成那些看起来（但仍然是）随机的序列。
（如：用户可能觉得随机6次骰点都是1的概率很低，那么如果出现这种情况就重骰，这本质上破坏了随机。）

## Q1：怎么能确定这些数字是真正随机的？

从理论上说，不可能证明一个随机数发生器确实随机。更准确地说，你会分析某个发生器产生的越来越多的数字，并且根据分析结果，你对这个发生器的信心会增加（也可能降低，视情况而定）。本页面持续更新的实时统计内的所有测试信息，基于国标《GM/T 0005-2021 随机性检测规范》中描述的15种随机性检测方法进行检测。

## Q2：如果我觉得掷骰子或抛硬币的结果看起来不太随机，怎么办？

有时会有人抱怨，说他们觉得骰子生成产生了太多大失败、大成功等数字，这类担忧很好地说明了人类处理随机性有多困难。人的大脑非常擅长寻找模式，所以即使不存在模式，我们也往往会看见模式。（这正是统计检验有用的原因，也是本页面实时统计会公开发布的原因。）

我们以掷五个六面骰为例来算一下。直觉上，你可能会预期五次掷出的结果在很多时候都应该不同。（至少这是人们在邮件中经常提到的想法。）那么，五次结果全部不同的概率是多少？第一个骰子很简单，六个可能值中的任意一个都可以（不会造成重复），概率是 6/6 = 1。掷出第一个骰子之后，第二个骰子与第一个不同的概率是 5/6，因为现在少了一个你还没有见过的值。第三个骰子是 4/6，依此类推。因此，五个骰子全部不同的总概率是：

6/6 x 5/6 x 4/6 x 3/6 x 2/6 ~= 9.26%

因此，如果你反复掷五个骰子，应该预期超过 90% 的结果中会包含重复。如果你掷六个骰子，可以在上面的数值上再乘以 1/6，得到大约 1.54%。因此，如果你反复掷六个骰子，预计大约每 65 次才会出现一次六个值全都不同。下表给出了这些概率：

| 同时掷出的骰子数量 | 出现重复的概率 |
| --- | --- |
| 1 | 0% |
| 2 | 约 16.7% |
| 3 | 约 44.4% |
| 4 | 约 72.2% |
| 5 | 约 90.7% |
| 6 | 约 98.5% |

如果对这些数据感兴趣，或许可以研究一下概率论。

## Q3：这些数字符合本福特定律吗？

不符合。[本福特定律](http://en.wikipedia.org/wiki/Benford%27s_law)描述的是许多现实数据集中首位数字里较小数值（尤其是“1”）出现过多的现象。本福特定律可以在按对数分布的数字中观察到，许多人类处理的数字都属于这种情况，但原则上说，本网站生成的随机数并不这样。像骰子一样，本网站提供的算法应当生成的是均匀分布的数字。因此，在较低范围的首位数字中不会出现过度代表。如果你不信，可以多次掷一个普通六面骰并记录结果。你不会在得到的值上观察到本福特定律。

## Q4：原始随机比特和实际骰点是如何对照的？
实现流程是“先取原始随机数，再映射到目标区间”。
系统底层随机源会先输出一个 Uint64() 值，也就是 64 位原始随机数据；
随后掷骰逻辑调用统一的区间映射函数，把这个值转换成 1..N 之间的整数，其中 N 是骰子的面数。例如 d6 会映射到 1..6，d100 会映射到 1..100。
技术上，这一步不可以直接做简单取模。当前的处理方式为：
1. 对于 2 的幂次范围，会使用位掩码快速映射；
2. 对于其他范围，会使用拒绝采样（rejection sampling）来避免取模偏差，确保每个点数的理论概率一致。
原始随机比特并不是和某个固定骰点一一硬编码对应，而是先作为均匀随机输入，再经过无偏映射得到最终结果。
